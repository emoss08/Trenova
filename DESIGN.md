# Design System: Trenova

`client/packages/shared/src/styles/tokens.css` is the source of every value below; if the two ever disagree, the CSS is right and this file is stale. `docs/engineering/design-system.md` is the implementation manual: which utility to reach for, and why each rule exists. This file records the system's character and invariants. The frontmatter carries the light theme and the core dark surfaces; the full dark ladder lives in `tokens.css`.

## Overview

**Creative North Star: "Drawn in Ink"**

Trenova is a working drawing. The page is paper, the structure is hairline, the primary action is ink, and almost nothing else is coloured. That restraint is what gives colour its job: on a Trenova screen a tone is a severity, an accent is a category, and blue is something you can follow or something you have hold of. If a colour means nothing, it is not on the page.

The system is dense, exact and calm. Dense because a dispatcher reads hundreds of rows a day, so body text is 12px and a table row is 30px, deliberately tighter than the product's peers. Exact because everything aligns: figures sit in tabular numerals, corners take one of two sizes, and a surface is told from the one beneath it by a line rather than a blur. Calm because nothing on a working screen moves unless work is running, and a state, however long it lasts, is drawn still.

The Desk is the one room with its own light. It sits outside the app shell, may wash an agent's accent across a column while the agent works, and has a small lamp drawing as the product's one illustration. Even there the wash is near-invisible, because the point is depth rather than colour. Geist is where the palette and type came from, and that is all it is: Trenova's own rules decide new work.

**Key Characteristics:**

- Greyscale chrome in true neutrals, with no warm or cool lean.
- Ink primary action; blue reserved for links, focus and selection.
- Two themes that mirror each other step for step.
- Tight corners and flat surfaces, with depth from hairlines and lightness steps.
- Sentence-case labels and aligned figures at 11 to 13px.
- Motion only in answer to an action, or for as long as work runs.

## Colors

A true-neutral paper-and-ink ground, with colour held back for severity, category and affordance.

### Primary

- **Working Ink** (`--ink`, `--foreground`): the filled primary button, and all primary text. It has its own hover and pressed rungs because a fill needs them and text does not. In dark it is the light end of the ramp (Dark Ink), so hover steps down in lightness rather than up.

### Secondary

- **Follow Blue** (`--brand`, `--ring`, `--info`): links, the focus ring, selected rows and checked boxes, the first chart series. It says "you can follow this" or "you are here". The info tone is this same blue, so a link and an "In transit" badge are told apart by form: bare text against a tinted label.

### Tertiary

- **Selection Amber** (`--selection`): selected text, in both themes, always with dark ink on it because near-white text on amber reads at under 2:1.

### Neutral

- **Paper Ground** (`--canvas`, `--sunken`): the page, the sidebar, and wells inside a panel.
- **Panel White** (`--card`, `--raised`, `--overlay`, `--field`): panels, cards, dialogs and form-control fills, and the ink on a filled button.
- **Hover Wash** and **Press Wash** (`--surface-hover`, `--surface-active`): interaction fills, kept separate from surfaces so a hover never borrows a container's colour. Press Wash is also the active nav row.
- **Muted Graphite** and **Subtle Graphite** (`--foreground-muted`, `--foreground-subtle`): secondary text and column heads. Subtle Graphite is the lightest text that clears AA on Paper Ground.
- **Faint Graphite** (`--foreground-faint`): placeholder dashes and decoration beside a value, never the value.
- **Hairline**, **Divider** and **Strong Hairline** (`--border`, `--border-subtle`, `--border-strong`): component outlines, dividers inside a component, and hover or emphasis.

### Tones

Severity, ordered, and chosen by what the operator should do. Each tone has a solid, a readable text rung, a tint and an edge.

- **Stop Red** (`--danger`): failed, refused, destructive.
- **Caution Amber** (`--warning`): needs attention soon. It is the one solid dark ink lands on (Caution Amber Ink), in both themes.
- **Clear Green** (`--success`): done, paid, passed.
- **Info** and **Neutral**: information uses Follow Blue, and a tone with no severity uses the greys.

### Categories

Eight accents (`--accent-indigo`, teal, amber, rose, emerald, sky, violet, slate) for sets with no ordering: a duty status, a pricing method, W-2 versus 1099. The same hues drive chart series (`--chart-1` to `--chart-8`) and agent identity, so a teal series and a teal agent are the same teal. **Nova Blue**, **Nova Violet** and **Nova Rose** belong to the Nova badge alone.

### Named Rules

**The Colour Must Mean Rule.** A tone is a severity, an accent is a category, and blue is place or affordance. Colour used for anything else is a defect.

**The Ink Button Rule.** The primary action is ink, never a hue. A blue primary button would cost blue its meaning.

**The Ordering Rule.** If a set has an ordering, use a tone; if it has none, use an accent. If you cannot decide, it has an ordering.

**The Act-On-It Rule.** Pick a tone by what the operator should do, not by what the thing is called. An overdue invoice is a warning; a shipment in transit is info, because nothing is wrong with it.

## Typography

**Display Font:** Geist Variable (with Inter Variable, then the system sans)
**Body Font:** Geist Variable
**Label/Mono Font:** Geist Mono for figures (with IBM Plex Mono); JetBrains Mono for source code only
**Serif Voice:** Newsreader Variable, for a few spoken moments

**Character:** One quiet grotesque carries nearly everything, so hierarchy comes from size and weight rather than from font changes. The mono exists so that figures line up, and the serif appears only where the product speaks to a person rather than presents a record.

### Hierarchy

- **Display** (600, 30 to 36px): rare large figures and headers.
- **Headline** (600, 24px, 30px line): page headers.
- **Page Title** (600, 15px, 20px line): the title in the 44px page bar, and section titles.
- **Card Title** (600, 13px, 18px line): card titles and form sections.
- **Panel Title** (600, 12px, 17px line): the 36px header of a section panel.
- **Body** (400, 12px, 17px line): the default, including table cells and values. Comfortable body is 13px; dense body is 11px and is the workhorse in tight layouts.
- **Label** (500, 11px, 16px line): column heads, field labels and badges. Button text is the same weight at 12px.
- **Micro** (500, 9 to 10px): dense table micro-labels and meta; 9px is the floor.
- **Figure** (400, 12px, mono, tabular): load numbers, IDs, currency and timestamps that must align in a column.
- **KPI** (600, 17px, tabular): the number in a figure strip. The one strip that leads a dashboard takes 20px.
- **Serif Voice** (400, 44px, 1.08 line): the Desk greeting, the public tracking headline, and a phrase in a settings hero.

### Named Rules

**The Three Weights Rule.** 400 is for values, 500 for labels, 600 for headings. A value in a cell takes no weight class at all.

**The Sentence Case Rule.** Labels are sentence case. `uppercase` is only for data that is uppercase, such as a SCAC, a state code or a VIN.

**The Whole Pixel Rule.** Every step is a whole pixel and brings its own line height. Never write an arbitrary size such as `text-[11px]`, because `text-xs` is already 11px.

## Layout

The app has one shell and no global header. A 48px rail on the left holds the organization mark, one tile per module, then notifications, settings and the user. Beside it, a 224px panel (dragged between 200 and 320px, folded with ⌘B) holds search and the pages of the current module. Below `md`, the rail and panel come out together as one sheet.

Every page is one layout with one 44px page bar. A list page bleeds: when a data table is the body's only child, the table runs edge to edge with no outer box. Everything else gets a 16px gutter and 16px gaps. A full-height workspace fills the viewport and scrolls inside, with no height computed from the chrome above it.

Row rhythm is a token: 30px body rows, 26px compact, 32px header rows, 10px horizontal cell padding. Two tables on one screen line up because they spend the same tokens. A denser table repoints the row token rather than patching its cells.

The Desk takes the whole viewport in three columns under one 48px strip: a 272px rail, the conversation, and a workspace at `clamp(26rem, 42%, 44rem)`, which keeps tables readable and caps conversation prose near 70 characters. Below `lg` the rail becomes a sheet.

The driver portal is a single column at most 512px wide, with a 56px header and a five-tab bar fixed to the bottom, inset for the device's safe area.

### Named Rules

**The Cab Floor Rule.** Desktop density is for office screens. On the driver portal, anything a driver reads to do the job is at least 15px (Portal Read), a form input is at least 17px (Portal Input, since iOS zooms the page when a focused input is under 16px), and every control is at least 48px tall with 8px between neighbours. Facts a driver acts on are set in full ink, not graphite. This is the target: the portal does not meet it yet.

**The One Layout Rule.** A page that builds its own top bar is a bug.

## Elevation & Depth

Trenova is flat by default. A surface is told from the one beneath it by a hairline and a step in lightness. Tables, fields, cards and panels never draw a shadow, because a blur is the one thing on a dense screen that cannot be aligned to anything. The `--elevation-*` tokens exist with no value, so a stray `shadow-md` lands on nothing.

Things that sit above the page and can be picked up get a lift, named by where it is allowed rather than by how big it is. A lift is a hairline ring plus a whisper of neutral shadow, and should be felt before it is seen.

Floating surfaces are inverted: anything that floats from a trigger (menus, selects, popovers, hover cards, tooltips) is dark in the light theme, and toasts are dark in both. Dialogs and sheets are not, because they replace the page rather than float over it.

### Shadow Vocabulary

- **Lift whisper** (`box-shadow: 0 0 0 1px color-mix(in oklch, var(--foreground) 8%, transparent), 0 1px 2px -1px oklch(0.2 0 none / 0.08)`): a hairline ring and one pixel of depth.
- **Lift** (`box-shadow: 0 0 0 1px color-mix(in oklch, var(--foreground) 8%, transparent), 0 2px 4px -2px oklch(0.2 0 none / 0.1), 0 6px 16px -8px oklch(0.2 0 none / 0.12)`): something you could pick up, such as a floating composer or a card in flight.
- **Lift float** (`box-shadow: 0 0 0 1px color-mix(in oklch, var(--foreground) 8%, transparent), 0 4px 8px -4px oklch(0.2 0 none / 0.12), 0 16px 40px -16px oklch(0.2 0 none / 0.18)`): something over everything else, such as a switcher.

### Named Rules

**The Flat Page Rule.** Nothing that sits in the page draws a shadow. A table row with a lift is a defect.

**The One Ring Rule.** Focus is one ring everywhere: Follow Blue at 3px, spent through the shared focus utilities and never assembled by hand. An invalid control repoints the ring to red rather than adding a second one.

## Shapes

Corners are tight and there are only two sizes, so a corner can say something. Labels (badges, chips, counts, filter pills) take a 4px corner and read as marks on a row. Controls and surfaces take 6px. The whole Tailwind radius scale is pointed at these values, so another corner has nowhere to land.

Round is kept for what is actually round: avatars, status dots, switch tracks and icon-only round buttons.

Icons sit on a 24px grid with a 2px round-capped stroke in the current text colour.

### Named Rules

**The No Pill Rule.** A label is never a pill. Anything holding a word takes the 4px corner.

**The One Meaning Rule.** An icon means one thing. An invoice wears the invoice icon; a receipt says something was paid.

## Components

Tight and exact. Small corners, flat fills and a slight give on press, so a control reads as an instrument rather than an object.

### Buttons

- **Shape:** gently squared (6px), 32px tall at the default size, with sizes from 18 to 36px for dense toolbars.
- **Primary:** Working Ink with Panel White text.
- **Hover / Focus:** a colour step on the swift curve, a 2.5% give on press, and the shared focus ring.
- **Destructive:** Stop Red, with the ring repointed to red.
- **Outline / Ghost / Quiet / Link:** outline is a Panel White fill with a hairline; ghost and quiet are bare until hovered; link is Follow Blue text.
- **Loading:** a spinner replaces the content and the button disables itself. A button can carry its keyboard shortcut as a key cap.

### Chips

- **Style:** the badge is the system's label: 20px tall, 4px corner, 11px medium text. It has two independent axes: variant (a tone or a categorical accent) and appearance (subtle, solid or outline).
- **State:** subtle is the default, with a tint, its edge and its readable text. A solid warning uses dark ink, which the component handles itself.

### Cards / Containers

- **Corner Style:** 6px.
- **Background:** Panel White on Paper Ground.
- **Shadow Strategy:** none; see Elevation & Depth.
- **Border:** one hairline.
- **Internal Padding:** 16px, or 12px at the small size. A header with a rule takes the sunken ground, so a panel reads as titled.

### Inputs / Fields

- **Style:** Panel White fill, one hairline, 6px corner, 28px tall. One shared field utility owns every state of every control.
- **Focus:** the one focus ring. A trigger with an open popup holds the same ring.
- **Hover:** the hairline steps to Strong Hairline; the fill does not change.
- **Error / Disabled:** invalid is a Stop Red hairline, tint and ring. Disabled is a sunken fill at 60% opacity.

### Navigation

- **Rail:** 32px tiles in a 48px rail, with hairlines between domains. The active tile is filled with Press Wash and ink. One hover fill glides from tile to tile rather than each tile lighting up. A count on a tile's corner is work waiting behind that module.
- **Keyboard:** `G` then a module's letter jumps there from anywhere.
- **Tabs:** the active tab is underlined in ink, not blue.
- **Mobile:** below `md`, the rail and panel become one sheet. The driver portal uses a bottom tab bar.

### Figure Strip

A row of figures is one joined strip divided by hairlines, never a row of floating cards. Label over number, no decorative icon, and a delta as small toned text with an arrow. A cell can act as a filter, and then fills with the selected wash when active.

### Assist Mark and Nova Badge

Anything the system suggests, drafts or fills in carries the assist mark: the diamond of an advisory road sign with a point at its centre, because a suggestion's standing with a dispatcher is "take this into account". Nova itself is shown by one mark, a hollow disc swept with Nova's three colours, which turns only while Nova is working.

### Artifact Chrome

Everything an agent produces sits in one frame: 6px corner, one hairline, a 48px header with the kind's mark in a sunken well, the title over one line of provenance, and a status badge only when the status is not Ready. No shadow. The kind is never coloured.

## Do's and Don'ts

### Do:

- **Do** make the primary action Working Ink, and pick the variant rather than writing a colour.
- **Do** use a semantic token for everything. If none fits, add one to `tokens.css`.
- **Do** set load numbers, IDs, currency and timestamps in Geist Mono with tabular numerals.
- **Do** draw a page's loading state as its own layout in the shimmer, with every section where the real one lands.
- **Do** write an absent value as an em dash, never a hyphen.
- **Do** say "New {thing}" in sentence case on every create action.
- **Do** run a loop only for as long as the work it describes, and only on `transform` and `opacity`.
- **Do** honour `prefers-reduced-motion`; every animation collapses to a cut.
- **Do** keep every layout working in English, Spanish, Traditional Chinese and Simplified Chinese.
- **Do** meet the Cab Floor Rule on new driver portal work.

### Don't:

- **Don't** write a raw palette class such as `bg-amber-500`, or an opacity tint such as `bg-warning/10`.
- **Don't** spend blue on a primary button, an active nav row or a severity.
- **Don't** use a shadow on anything that sits in the page.
- **Don't** put `rounded-full` on anything that holds a word.
- **Don't** write `uppercase tracking-wider` on a section label, a column head or a badge.
- **Don't** use sparkles, magic wands or any glyph that promises magic for machine work; use the assist mark.
- **Don't** make the assistant a chat widget with cards in it; agent output is an artifact in its frame.
- **Don't** let anything on a working screen move by itself: no looping shimmer on a badge, no pulsing glow, no floating sparkle.
- **Don't** raise a toast for an outcome the person can already see.
- **Don't** use a spinner as a page or section loading state.
- **Don't** build a row of floating KPI cards; use the joined strip.
- **Don't** carry desktop density onto the driver portal.
